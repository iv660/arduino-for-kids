# Навык: Создание уроков по Arduino для детей 9 лет

## Описание
Этот навык генерирует полный урок по Arduino с соблюдением структуры и принципов, используемых в проектах "01. Blink" и "02. Button".

## Целевая аудитория
- Дети 9 лет
- Минимальные знания программирования
- Практико-ориентированный подход
- Минимальное знание английского для понимания кода

## Ключевые требования и принципы

### Язык и общение
- Язык документации и комментариев — русский
- Минимализировать программистский сленг (вместо "инициализация" — "подготовка", вместо "флаг" — "переменная, которая запомнит")
- Все профессиональные термины (setup, loop, OUTPUT, INPUT_PULLUP, HIGH, LOW) должны иметь пояснения в контексте или в словарике
- Формулировки простыми словами, близкими к повседневному опыту ребёнка

### Архитектура кода (Clean Code для верхних слоёв)
- **Принцип "сверху вниз"**: по верхнеуровневому коду в loop() должен быть очевиден основной принцип работы проекта
- **Вспомогательные функции** — это инструменты, помощники, которые скрывают детали реализации
- **Простые условия:** избегаем сложных условий с несколькими проверками в одной строке. Отдаём предпочтение последовательным проверкам с понятным `return` после каждой из них. Если проверка всё равно получается сложной, выносим её в отдельный вспомогательный метод с понятным именем.
- Пример хорошего верхнеуровневого кода:
  ```cpp
  void loop() {
      if (buttonWasPressed()) {
          toggleBlinking();
      }
      if (isBlinking && timeElapsed()) {
          toggleLight();
      }
  }
  ```
  Сразу ясно: проверяем кнопку, переключаем мигание, считаем время.

### Порядок этапов обучения
1. **Первый этап урока** — создание верхнеуровневого алгоритма (loop() логика)
   - В README показываем loop() с ясной логикой
   - В main.cpp все вспомогательные функции объявлены и содержат стабовые возвращаемые значения, но реализация отложена
   - Это позволяет собрать и понять архитектуру проекта ДО реализации деталей
   - **Порядок инструкций обязателен:** руководство по реализации всегда начинается с главного, верхнеуровневого алгоритма в `loop()`. Только после него даём инструкции по реализации методов классов и других деталей.
   
2. **Последующие этапы** — пошаговая реализация каждой функции
   - Каждый шаг реализует одну функцию полностью
   - Ребёнок не перегружается информацией, поэтапно заполняет каркас

Пример:
```cpp
// ЭТА ЗАГОТОВКА СОДЕРЖИТ СТАБЫ
bool buttonWasPressed() {
    return false;  // TODO: реализовать
}

void loop() {
    // ЭТА ЛОГИКА УЖЕ ЯСНА, МОЖНО СОБРАТЬ И ПОНЯТЬ АРХИТЕКТУРУ
    if (buttonWasPressed()) {
        toggleBlinking();
    }
}
```

## Структура урока

Каждый урок состоит из трёх частей:

### 1. platformio.ini
Стандартная конфигурация для Arduino Leonardo:
```ini
[env:leonardo]
platform = atmelavr
board = leonardo
framework = arduino
upload_port = COM15
```

### 2. README.md — пошаговая инструкция

**Структура документа:**

1. **Заголовок (H1)** — название урока (чтобы даже название было понятно 9-летнему)
2. **Вводный абзац** — одно-два предложения о том, чему научимся (простой язык, конкретный результат)
3. **"Что нам понадобится" (H2)** — список всех компонентов (Arduino Leonardo, кабель, компьютер и т.д.)
4. **"Собери свою схему!" (H2)** — ЕСЛИ требуется электрическая схема:
   - Описание компонентов и пинов
   - **Варианты сборки** (один или несколько):
     - **На макетной плате** — инструкция с номерами пинов и проводами
     - **На конструкторе "Знаток"** — инструкция для модульной системы
     - **Комбинированный вариант** — оба способа в одном разделе
   - Ссылка на SVG-схему(ы) — для каждого варианта сборки отдельная схема или одна универсальная
5. **Этапы (H2 — "Этап N: ..." или "Как это работает")**  — основная часть урока
   - Если в уроке только один этап, не добавлять к его заголовку номер и слова «Этап 1:». Использовать только понятное название результата, например: «Кнопка запускает реле на 10 секунд».
   - **"Что здесь происходит" (H3)** — краткое описание на простом языке (2-3 предложения)
   - **"Как реализовать" (H3)** — пошаговые шаги
     - **Шаг 1: Высокоуровневый алгоритм** или **Шаг 1: Как работает программа**
       - Показываем loop() с комментариями, объясняем логику
       - Все вспомогательные функции здесь вызываются, их реализация придёт позже
     - **Шаг 2+: [Название]** — каждый шаг реализует одну функцию:
       - Одно-два предложения пояснения (что делает, зачем)
       - Полный код функции с реализацией
       - Дополнительное пояснение (если логика нетривиальна)
6. **"Запуск программы" (H2)** — инструкция по загрузке:
   ```bash
   platformio run --target upload
   ```
   + ожидаемый результат
7. **"Экспериментируй!" (H2)** (опционально) — вариации для самостоятельных попыток
8. **"Словарик" (H2)** — определения всех использованных терминов на уровне 9-летнего:
   - **Термин** — простое объяснение (не более 10-15 слов)
   - **HIGH** — "включить" (подать напряжение)
   - **OUTPUT** — режим, когда пин выдаёт сигналы (выход)

**Требования к текстовой части:**
- Язык простой, без профессиональных термов (или объяснять их сразу)
- Активный залог, прямые команды ("Напиши...", "Добавь...", "Посмотри...")
- Короткие предложения
- Частое использование смайлов для визуального интереса 💡🔌🎉
- Аналогии из жизни (часы, кнопка, свет, автомобиль)

### 3. src/main.cpp — каркас кода (бойлерплейт)

**Принцип:** заготовка содержит бойлерплейт (объявления, инициализацию, setup) и стабовые реализации вспомогательных функций, чтобы проект компилировался на любом этапе. Ребёнок самостоятельно вводит реальную логику в функции и loop() согласно инструкциям в README.

**Архитектура заготовки:**

1. **Всегда начинается с:**
   ```cpp
   #include <Arduino.h>
   ```

2. **Объявления пинов и глобальных переменных** — с понятными комментариями на русском:
    ```cpp
    const int ledPin = 5;           // Пин светодиода
    bool isActive = false;          // Переменная для запоминания состояния
    unsigned long lastTime = 0;     // Когда мы в последний раз что-то делали?
    ```
   - **Никаких магических чисел:** номера пинов, интервалы времени и другие важные числа всегда выносим в переменные или константы с понятными именами. Например: `const int buttonPin = 3;`, `const unsigned long timerInterval = 10000;`.

3. **Вспомогательные функции** (в порядке использования в loop):
   - **Стабовые реализации** — каждая функция содержит заглушку со стабовым возвращаемым значением:
     ```cpp
     // Проверяет, нажата ли кнопка
     bool buttonIsPressed() {
         return false;  // TODO: реализовать проверку нажатия кнопки
     }
     
     // Включает светодиод
     void turnLightOn() {
         // TODO: реализовать включение светодиода
     }
     ```
   - **Назначение стабов:** позволяет проекту компилироваться и собраться без ошибок на любом этапе обучения
   - **TODO-комментарии:** допустимы и уместны, помогают ребёнку понять, что именно нужно реализовать в этом месте
   - **Реальная логика:** ребёнок заполняет вместо стабов согласно инструкциям в README
   - Комментарии объясняют, что функция должна делать

4. **setup()** — полная реализация:
   ```cpp
   void setup() {
       pinMode(ledPin, OUTPUT);
       pinMode(buttonPin, INPUT_PULLUP);
   }
   ```
   - Полностью готова к использованию с первого дня
   - Содержит все необходимые инициализации

5. **loop()** — только скелет (пустая функция):
   ```cpp
   void loop() {
       // Ребёнок заполнит эту функцию согласно инструкциям в README
   }
   ```
   - **ПОЛНОСТЬЮ ПУСТАЯ** или содержит только комментарий-подсказку
   - **Никаких реализаций** — ребёнок вводит код полностью самостоятельно
   - Первый шаг в README показывает, что должно быть в loop()

6. **Комментарии:**
   - Описательные комментарии к переменным (на русском, объясняют смысл)
   - Описательные комментарии к функциям (что они должны делать)
   - **TODO-комментарии в стабах** — приветствуются, помогают ребёнку понять, что реализовать
   - **НИКОГДА** закомментированный рабочий код

## Процесс создания нового урока

### Шаг 0: Уточнение требований

Перед написанием текста задать вопросы и убедиться в ответах:

1. **Название урока** — конкретное действие, результат, который видит ребёнок
   - Пример ✓: "Управление сервомотором", "Датчик дыма"
   - Пример ✗: "Работа с прерываниями", "Конфигурация таймера"

2. **Одна чёткая цель** — какое ровно одно действие получится делать в конце?
   - Пример: "Светодиод будет включаться по нажатию кнопки и гаснуть при отпускании"

3. **Компоненты** — полный список (пины, компоненты, кабели)
   - Arduino Leonardo, кабель USB, компьютер
   - Светодиод, резистор, кнопка, провода
   - Конкретные номера пинов

4. **Нужна ли электрическая схема?** — если да, уточнить методы сборки:
   - Какие варианты сборки требуются или возможны?
     - **Макетная плата** (breadboard) — классический вариант с проводами
     - **Конструктор "Знаток"** — модульная система
     - **Комбинация** — оба способа в одном уроке
   - "Какие пины используются? Как они подключены к компонентам?"

5. **Этапы/Усложнения** — планируется ли разделить на несколько уровней?
   - Пример: Этап 1 (простое включение), Этап 2 (toggle), Этап 3 (мигание)
   - Или один единственный этап

6. **Новые функции** — какие вспомогательные функции нужны?
   - Перечислить с кратким описанием ("функция проверяет, нажата ли кнопка", "функция включает светодиод")

7. **Ожидаемые ошибки** — какие ошибки может допустить ребёнок? (для словарика и пояснений)

### Шаг 1: Создать структуру папки

```
NN. Название/
├── platformio.ini
├── README.md
├── src/
│   └── main.cpp
├── .gitignore
└── schematic.drawio.svg (если нужна схема)
```

### Шаг 2: Написать main.cpp

**Порядок:**
1. Заголовок `#include <Arduino.h>`
2. Объявить все глобальные переменные и константы
3. Объявить все вспомогательные функции (с комментариями, со стабовыми значениями для bool/int)
4. `setup()` — полная реализация
5. `loop()` — верхнеуровневая логика, вызывает функции

### Шаг 3: Написать README.md

Следовать структуре выше. Убедиться:
- Первый шаг показывает loop() и объясняет логику
- Последующие шаги реализуют функции одна за другей
- Язык простой, нет жаргона

### Шаг 4: Запросить/создать SVG-схему (если нужна)

## Примеры формулировок (на уровне 9-летнего)

### Плохо ❌
- "Инициализируем пины в режиме OUTPUT"
- "Настройте состояние переменной логического типа"
- "Функция обнаруживает фронт сигнала"
- "Используем побитовую операцию AND для маскирования"

### Хорошо ✓
- "Скажем Arduino, что пин 5 — это выход для светодиода"
- "Создадим переменную, которая запомнит, включена ли лампа (true или false)"
- "Функция заметит, когда кнопка только что была нажата (перешла с отпущенной на нажатую)"
- "Проверим, включена ли переменная, и если да, то сделаем..."

### Примеры пояснений терминов

**OUTPUT** — режим пина "на выход": пин отправляет сигнал из Arduino (например, включает светодиод)

**HIGH** — значит "включено" (подано напряжение); **LOW** — значит "выключено" (напряжения нет)

**setup()** — функция, которая запускается один раз в самом начале, когда мы включаем Arduino (используем её для подготовки пинов)

**loop()** — функция, которая повторяется снова и снова, пока Arduino включена (главный цикл нашей программы)

## Проверка перед публикацией

Убедиться, что:

- [ ] Название урока понятно и точно описывает результат
- [ ] Вводный абзац заканчивается ясным результатом ("...и светодиод будет мигать")
- [ ] Первый шаг (или "Как работает программа") показывает loop() с ясной логикой
- [ ] Каждый последующий шаг реализует одну функцию полностью
- [ ] Код примеры содержат реальные номера пинов, не переменные
- [ ] Словарик охватывает все термины, используемые в уроке
- [ ] main.cpp компилируется (все функции объявлены, setup() и loop() присутствуют, есть стабовые значения)
- [ ] Нет закомментированного кода
- [ ] Язык простой, предложения короткие
- [ ] Все профессиональные термины (OUTPUT, loop, HIGH, и т.д.) либо объяснены в тексте, либо есть в словарике
- [ ] Использованы аналогии из жизни (часы, кнопка, автомобиль, и т.д.)

## Использование навыка

Когда пользователь запрашивает новый урок:

1. **Задать уточняющие вопросы** из Шага 0 (все 7 пунктов)
2. **Получить полную информацию** перед началом создания
3. **После согласования создать:**
   - папку `NN. Название/`
   - файл `platformio.ini`
   - файл `src/main.cpp` с заготовками и стабами
   - файл `README.md`
   - (опционально) `schematic.drawio.svg` или запросить SVG-файл у пользователя
4. **Показать пользователю предпросмотр** перед публикацией
5. **Готово!** Урок опубликован и готов к использованию
